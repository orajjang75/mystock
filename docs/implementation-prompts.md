# 구현 프롬프트 (단계별)

사용 방법
- PRD 문서를 레포의 `docs/PRD.md`로 저장한 뒤, 아래 프롬프트를 번호 순서대로 Claude Code에 붙여 넣는다.
- 각 단계 끝의 "완료 기준"을 통과하면 다음 단계로 간다. 통과 못 하면 같은 단계에서 수정한다.
- 모든 프롬프트는 "docs/PRD.md를 먼저 읽고"로 시작한다. 장 번호는 PRD의 장 번호다.
- 한 단계가 끝날 때마다 git 커밋을 남긴다.

## 0단계. 작업 규칙 고정 (CLAUDE.md)

```
docs/PRD.md를 처음부터 끝까지 읽어 줘. 그다음 레포 루트에 CLAUDE.md를 만들어 아래 규칙을 적어 줘.

- 이 앱은 알림 전용이다. 주문·자동매매 코드는 어떤 경우에도 넣지 않는다.
- 신호 계산식은 PRD 6장 표가 유일한 정의다. 표와 코드가 다르면 코드를 고친다. 정의를 바꿔야 하면 먼저 나에게 묻는다.
- 지표·신호 함수는 pandas 벡터화 순수 함수로 만들고, 스크리너·알림·백테스트가 같은 함수를 import해서 쓴다.
- 직전은 바로 앞 봉, 현재는 마감이 확정된 최신 봉이다. 확정되지 않은 봉으로 신호를 내지 않는다.
- 상승은 빨강, 하락은 파랑이다.
- 백엔드는 FastAPI, 프런트는 React + TypeScript + antd, 가격 차트는 Lightweight Charts, 그 밖의 차트는 ECharts다. Recharts는 쓰지 않는다.
- 새 기능은 테스트와 함께 커밋한다. 모의 데이터로 돌아가야 하고, 실제 시세 소스는 어댑터만 교체한다.

완료 기준: CLAUDE.md가 만들어지고, 네가 읽은 PRD의 핵심 규칙 5개를 한 줄씩 요약해서 내가 확인할 수 있게 보여 줘.
```

## 1단계. 프로젝트 골격과 데이터베이스

```
docs/PRD.md의 8장(시스템 아키텍처와 데이터)을 기준으로 프로젝트 골격을 만들어 줘.

- 루트에 backend/(FastAPI, Python 3.11+, uv 또는 pip-tools), frontend/(Vite + React + TypeScript), docker-compose.yml(PostgreSQL)을 둔다.
- backend는 app/ 아래에 api, core(설정), db(모델·세션), adapters(시세 소스), engine(지표·신호), services, jobs 패키지로 나눈다.
- SQLAlchemy 2.x와 Alembic으로 8장 테이블을 모두 만든다: instruments, ohlcv_daily, investor_flow_daily, ohlcv_intraday, scan_results, watchlist, holdings, cycles, alerts, settings, fills, backtest_runs. 컬럼은 표의 "주요 컬럼"을 따르고, 시계열 테이블에는 (종목코드, 일자 또는 봉 시각) 복합 유니크 키를 둔다.
- 단일 사용자 로그인(/api/auth/login, /api/auth/logout)을 세션 쿠키 방식으로 만든다. 계정은 환경 변수로 받는다.
- GET /api/health 를 만들어 DB 연결과 마지막 시세 갱신 시각을 돌려준다.
- pytest, ruff, mypy 설정과 Makefile(make dev, make test, make lint)을 만든다.

완료 기준: docker compose up 후 alembic upgrade head 가 성공하고, make test 와 make lint 가 통과하고, /api/health 가 200을 돌려준다.
```

## 2단계. 시세 어댑터와 모의 데이터

```
docs/PRD.md의 8장 "시세 소스" 항목과 S-1을 기준으로 시세 어댑터 계층을 만들어 줘.

- adapters/base.py 에 추상 인터페이스를 정의한다: 종목 목록·시가총액 순위 조회, 일봉 조회, 투자자별 일별 순매수 조회, 30분봉 조회, KOSPI 지수 일봉 조회(index_daily 테이블에 저장).
- adapters/mock.py: 재현 가능한 시드로 KOSPI 120개(상위 100 + 후보 여분), KOSDAQ 30개 종목의 일봉 500거래일, 30분봉 60거래일, 투자자별 순매수를 생성한다. 바닥 후 반등 패턴, 계속 하락, 횡보를 섞어서 스크리너 테스트에 쓸 수 있게 한다.
- adapters/pykrx_adapter.py: pykrx로 일봉·시가총액·투자자별 순매수를 가져온다. 네트워크가 막힌 환경에서도 import 오류가 나지 않게 지연 import 한다.
- adapters/kis_adapter.py: 한국투자증권 API로 30분봉을 가져오는 자리만 만든다(NotImplementedError와 TODO). 실제 연동은 11단계에서 한다.
- services/universe.py: 스캔 일자 기준으로 KOSPI 시가총액 상위 100개, KOSDAQ 상위 20개를 다시 순위 매기고 instruments 에 저장한다. 관리종목·거래정지·투자경고·위험 종목과 최근 20거래일 일평균 거래대금 10억 원 미만 종목을 제외하는 필터를 포함한다. 우선주 포함 여부는 설정값(기본 제외)으로 둔다.
- jobs/ingest.py: 어댑터에서 받은 데이터를 upsert 하는 수집 함수. 30분봉만 저장하고 60분봉은 조회 시 집계한다(정규장 09:00~15:30, 마지막 60분봉은 30분).
- 어댑터는 환경 변수 ADAPTER=mock|pykrx|kis 로 고른다.

완료 기준: 모의 어댑터로 수집 함수를 돌리면 DB에 일봉·분봉·수급이 채워지고, 60분봉 집계 결과의 마지막 봉이 30분 봉인지 테스트로 확인되고, universe 서비스가 정확히 KOSPI 100 + KOSDAQ 20개를 돌려준다.
```

## 3단계. 지표·신호 엔진 (가장 중요)

```
docs/PRD.md의 6장 표를 코드로 옮겨 줘. 이 단계가 앱의 핵심이므로 표의 정의를 그대로 따르고, 임의로 바꾸지 마.

backend/app/engine/ 에 아래를 만든다. 모두 입력은 pandas DataFrame(OHLCV), 출력은 같은 인덱스의 Series/DataFrame인 순수 함수이며, 반복문 없이 벡터화한다.

1) indicators.py: sma, rsi(14), macd(12,26,9), atr(14), obv, bollinger(20,2) — 볼린저는 하단·중심·상단과 %B, 밴드폭을 한 번에 계산해 DataFrame 하나로 돌려준다. 볼린저 관련 신호 4개는 모두 이 결과의 %B를 공유한다.
2) screener_signals.py: 거래대금 필터, 52주 낙폭, 이격도, 볼린저 하단 이탈 이력, RSI 상향 돌파, 강세 다이버전스(스윙 저점 확정 기준을 파라미터로), 볼린저 복귀, MACD 골든크로스(0선 아래만 인정 옵션), 종가의 20일선 회복, 5일선 우위, 하락 파동 고점 돌파, OBV 전환, 평균 대비 거래량(양봉 조건, 2배·3배 가산), 외국인 연속 순매수, 기관 연속 순매수, 외국인·기관 순매수 강도, 순매수 전환.
3) alert_signals.py: 매도 — RSI 과열 이탈, 볼린저 상단 복귀, MACD 약화, 약세 다이버전스, ATR 기반 이격도 과열, 수급 이탈. 재매수 — RSI 반등, 볼린저 지지, MACD 골든크로스, 가격 조건(재매수 목표가), 수급 필터.
   - 수급 이탈과 수급 필터는 분봉이 아니라 직전 확정 일봉까지의 (외국인 + 기관) 순매수 금액으로 계산한다. 수급 데이터가 없으면 신호를 건너뛰고 "수급 미반영" 플래그를 돌려준다.
4) params.py: 모든 기본값(−30%, −8%, N=3, 2%, 3배, 5거래일 등)을 하나의 pydantic 모델로 모으고, 설정 화면이 같은 모델을 쓰게 한다.
5) force_sell.py (A-13): 종목 5일선 이탈(직전 SMA5 ≥ SMA20 이고 현재 SMA5 < SMA20, 확정 일봉 종가 기준)과 KOSPI 지수 5일선 이탈을 같은 함수로 계산하고, 5일선이 20일선 위로 회복했는지 판정하는 함수도 만든다.
6) 재매수 목표가 = 직전 매도가 × (1 − 비용 − 목표 이득). 비용은 왕복 수수료 + 매도 거래세, 목표 이득 기본 1%.

테스트(tests/engine/): 지표마다 손으로 계산한 작은 합성 데이터로 경계값을 검증한다. 특히 (a) RSI가 29→30 일 때만 돌파, (b) MACD ≤ 시그널에서 > 시그널로 바뀌는 첫 봉만 골든크로스, (c) 확정되지 않은 마지막 봉 제외, (d) 볼린저 %B 경계(<0, >1), (e) 수급 데이터 결측 처리를 포함한다.

완료 기준: 6장 표의 모든 행에 대응하는 함수가 있고(표 행 → 함수명 대응표를 docs/signal-map.md 에 만들어 줘), 테스트가 모두 통과하고, 반복문 없이 120종목 × 500일 계산이 1초 안에 끝난다.
```

## 4단계. 스크리너 백엔드

```
docs/PRD.md의 4장(S-1~S-11)과 6장 점수 표를 기준으로 스크리너를 만들어 줘. 3단계의 engine 함수만 사용하고 계산식을 새로 쓰지 마.

- services/screener.py: universe 필터 → 바닥 게이트(52주 낙폭 AND (이격도 OR 볼린저 하단 이탈 이력)) → 반전 30점 / 확인 30점 / 거래량 20점 / 수급 20점 점수화. 구간 안에서는 신호별 균등 배분(반전 3개 각 10점, 확인 5개 각 6점, 수급 4개 각 5점), 거래량은 2배 14점·3배 20점. 수급 데이터가 없는 날은 수급 구간을 빼고 100점 기준으로 환산하고 "수급 미반영" 태그를 붙인다.
- 후보가 너무 적을 때 낙폭 기준을 완화하는 옵션과 하락률 순위 방식 옵션을 설정으로 둔다(S-2).
- 가중치와 최소 점수 컷을 설정에서 바꿀 수 있게 한다(S-6).
- 결과를 scan_results 에 날짜별로 저장하고, 충족 조건 태그와 근거 지표 값, 사용한 파라미터를 함께 저장한다(S-9, 재현성).
- watchlist 서비스(S-11): 스캔 대상 종목만 추가할 수 있고, 조회 시 최신 점수와 전일 대비 점수 변화를 돌려준다.
- jobs/daily_scan.py: 휴장일이면 건너뛰고, 수급 데이터가 확정되는 시각 이후에 돌도록 실행 시각을 설정으로 둔다. 스캔 시간을 로그에 남긴다(목표 10분 이내).
- API: GET /api/screener/results, POST /api/screener/run, GET /api/stocks/{code}/candles, GET /api/stocks/{code}/indicators(RSI, MACD, 볼린저 %B·밴드폭, OBV, ATR, 투자자별 순매수), GET·POST·DELETE /api/watchlist.

완료 기준: 모의 데이터로 POST /api/screener/run 을 실행하면 점수순 결과가 저장되고, "바닥 후 반등"으로 만든 모의 종목이 상위에 오르고 "계속 하락" 종목은 게이트에서 탈락하는 통합 테스트가 통과하고, 120종목 스캔이 10분보다 훨씬 빨리 끝난다.
```

## 5단계. 보유 종목과 매도·재매수 사이클

```
docs/PRD.md의 5장(A-1~A-11)과 5장 상태 흐름도를 기준으로 보유 종목 서비스를 만들어 줘.

- 상태: 보유 → 재매수 대기 → 재매수 완료(및 만료·포기). 상태 전환은 앱이 신호를 낸다고 바뀌지 않고, 사용자의 체결 기록(POST /api/holdings/{id}/fills)으로만 확정된다.
- A-1 보유 종목 등록(시작 수량 기록), A-3 매도 제안 수량(보유량의 1/3, 전량 매도 제안 금지), A-4 재매수 목표가 계산, A-5 재매수 제안 수량 = 매도 대금 ÷ 재매수가(수수료 반영), 수량 증가분 = 제안 수량 − 매도 수량.
- A-13 강제 매도: 종목 5일선 이탈이나 KOSPI 지수 5일선 이탈이 확정되면 겹침 조건·수급 필터·일봉 추세 필터·사이클당 1회 제한과 무관하게 전량 매도 알림을 낸다(KOSPI는 모든 보유 종목, 종목 이탈은 그 종목만). 체결을 기록하면 사이클을 종료하고, 해당 종목 5일선이 20일선 위로 회복하고 KOSPI도 5일선 > 20일선이 될 때까지 재매수 알림을 내지 않는다. 상태 전이 테스트에 이 경로를 포함한다.
- 사이클당 매도 1회. 재매수 대기 중에는 추가 매도 알림을 내지 않는다(A-2).
- A-6 일봉 추세 필터: 일봉이 하락 추세로 바뀌면 재매수 알림 대신 비중 축소 경고. 추세 판정 정의는 PRD에 없으므로, 먼저 "종가 < 60일선이고 60일선 기울기 < 0" 같은 후보 정의를 제안해서 나에게 확인받고 구현해 줘.
- A-7 재매수 대기 5거래일 만료, A-8 ATR 기반 손절선과 이탈 경고.
- A-11 신호 봉 길이(30분·60분·일봉, 기본 60분)를 설정에서 고른다. 일봉 방향 필터는 항상 함께 쓴다.
- services/alert_engine.py: 보유 종목마다 설정한 봉이 마감될 때, 매도 후보(RSI 과열 이탈, 볼린저 상단 복귀, MACD 약화, 약세 다이버전스, ATR 이격도 과열, 일봉 수급 이탈) 중 2개 이상 겹치면 매도 알림, 가격 ≤ 재매수 목표가이면서 재매수 후보(RSI 반등, 볼린저 지지, MACD 골든크로스) 중 2개 이상 겹치면 재매수 알림. 일봉 수급 이탈 상태면 재매수 알림을 보류하고 경고만 낸다.
- 사이클별 수량 증가분과 누적 결과 계산(A-9), GET /api/holdings, /api/holdings/{id}/cycles.

완료 기준: 상태 전이를 표로 정리한 테스트(보유→매도 체결→재매수 대기→재매수 체결/만료/포기)가 모두 통과하고, 수수료·세금 반영 후 수량 증가분이 손계산 예제와 일치하고, 수급 이탈 때 재매수 알림이 보류되는 케이스가 테스트로 확인된다.
```

## 6단계. 스케줄러와 알림

```
docs/PRD.md의 A-10, A-12, 8장 "분봉 작업"과 10장 비기능 요구사항을 기준으로 스케줄러와 알림을 만들어 줘.

- APScheduler 로 일봉 작업(장 마감 후, KOSPI 지수 일봉과 A-13 강제 매도 판정 포함)과 분봉 작업(정규장 중 봉 마감마다)을 등록한다. 휴장일과 장 시간 밖에는 건너뛴다.
- 데이터 신선도 검사: 시세 수집이 실패했거나 마지막 갱신이 오래되면 신호를 내지 않고 /api/health 와 화면에 경고를 남긴다.
- 봉 마감 후 1분 이내에 알림이 생성되는지 측정하는 지연 로그(봉 마감 시각, 알림 생성 시각)를 남긴다.
- alerts 서비스: 인앱 알림 저장, 같은 종목의 같은 신호는 설정한 봉 수 동안 중복 금지(쿨다운), 근거 지표 값과 사용한 파라미터 저장, 읽음 처리. API: GET /api/alerts(읽지 않음 필터), POST /api/alerts/{id}/read, POST /api/alerts/test.
- 앱 밖 알림 채널은 인터페이스(notifier)로 추상화하고, 텔레그램 봇 구현을 먼저 만든다. 메시지에는 종목, 신호 종류, 제안 수량, 재매수 목표가 요약만 담는다. 채널은 설정에서 켜고 끈다. 브라우저 푸시는 나중에 notifier 구현만 추가하면 되게 해 둔다.
- 증권사 키·텔레그램 토큰은 서버 환경 변수로만 보관하고 로그와 API 응답에 노출하지 않는다.

완료 기준: 모의 시계를 앞으로 돌리는 통합 테스트에서 봉 마감마다 알림이 생성되고, 쿨다운 안의 중복 신호는 막히고, 시세를 일부러 끊으면 신호가 멈추고 경고가 뜬다.
```

## 10단계. 백테스트와 검증

```
docs/PRD.md의 10장 "백테스트 계획"과 검증 기준 표를 기준으로 백테스트를 만들어 줘. 3단계의 engine 함수를 그대로 재사용하고 계산식을 복제하지 마.

- backtest/signal_quality.py: vectorbt 로 신호 품질을 본다. 후보 선정 후 5거래일 수익률 분포(중앙값 포함)를 buy&hold, 무작위 진입, KOSPI 지수와 비교한다. 수익률은 다음 봉 시가 체결로 계산해서 룩어헤드를 막는다.
- backtest/cycle_simulator.py: 별도의 순차 시뮬레이터. 보유 → 매도 → 재매수 대기 → 재매수/만료의 전체 사이클을 비용(수수료·거래세) 반영해서 돌리고, 사이클당 수량 증가율, 사이클 성공률, 최대 낙폭을 계산한다. 5장의 상태 머신 코드를 그대로 재사용한다.
- 사이클 시뮬레이터에 A-13 강제 매도(종목·KOSPI 5일선 이탈)를 포함하고, 강제 매도 빈도와 이후 수익을 리포트한다(휩쏘 위험 확인).
- 같은 신호 코드로 30분봉·60분봉·일봉을 같은 기간에 돌려서 봉 길이별 사이클당 수량 증가율을 비교한다.
- 파라미터 민감도 히트맵, 학습·검증 기간 분리(walk-forward)를 지원한다.
- 데이터 처리 규칙: 수정주가 사용, 상장폐지 종목 포함 여부(생존편향) 옵션, 시점별 시가총액 순위로 유니버스 구성. 모의 어댑터에서는 이 옵션이 동작만 하면 된다.
- API: POST·GET /api/backtests, backtest_runs 에 파라미터·결과 요약 저장.
- 화면: 기간과 파라미터 폼, 결과 요약, 거래 목록, 자산 곡선과 수량 증가 추이(ECharts), 파라미터 히트맵.

완료 기준: 모의 데이터로 백테스트가 끝까지 돌고, 룩어헤드가 없음을 확인하는 테스트(신호 봉의 다음 봉 시가로만 체결됨)가 통과하고, 결과를 프리셋으로 저장해 스크리너에 적용할 수 있다. 실데이터 결과로 6장 기본값을 확정하는 일은 내가 직접 하므로, 하지 말고 결과 리포트만 만들어 줘.
```

## 11단계. 실데이터 연동과 모의 운영

```
docs/PRD.md의 8장, 10장 리스크 표, 오픈 이슈를 기준으로 실제 시세 연동을 마무리해 줘.

- 먼저 오픈 이슈를 확인해서 나에게 물어 줘: 분봉 증권사 API(KIS 또는 키움), 수급 데이터 소스와 확정 시각, PostgreSQL vs TimescaleDB, 알림 채널. 답을 받은 뒤 진행해.
- adapters/kis_adapter.py 를 구현한다: 토큰 갱신, 호출 제한 준수, 응답 캐시, 30분봉 수집, 실패 시 재시도와 신선도 경고 연동. 키는 환경 변수로만 받는다.
- 분봉 보관 기간이 부족하면 어디까지 과거 데이터를 받을 수 있는지 조사해서 백테스트 가능 기간을 문서로 남긴다.
- 수수료율·거래세율 기본값은 구현 시점의 최신 값을 공식 자료로 확인해서 넣고 출처를 주석으로 남긴다.
- 모의 운영 모드: 실제 시세로 신호만 내고 체결 기록은 받지 않는 읽기 전용 운영을 몇 주 돌릴 수 있게 한다. 신호 누락과 지연을 일별로 요약하는 리포트(봉 마감 대비 알림 지연, 수집 실패 횟수)를 만든다.
- 배포: docker compose 로 backend, frontend, postgres 를 한 번에 올리는 설정과 .env.example, 백업 방법을 README 에 적는다.

완료 기준: 실제 시세로 하루 동안 돌려서 분봉 수집·신호 계산·알림이 오류 없이 끝나고, 지연 리포트가 생성되고, 모의 운영 중 신호 누락이 없다는 로드맵 5단계 게이트를 확인할 수 있는 숫자가 나온다.
```
